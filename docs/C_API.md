# Stick Shift Engine C API

> **Status: v0.1.0.** The API below is the contract
> [`crates/stickshift-capi`](../crates/stickshift-capi) implements. It is **asynchronous in shape**: calls return immediately with a handle or a
> result code, resources move from *pending* to *ready* or *failed*, and completions arrive as
> events. In v0.1 most work still happens synchronously inside the calls (see
> [What may wait in v0.1](#what-may-wait-in-v01)); later releases move it onto engine
> threads **without changing this API**.

The C API is a thin layer over the Rust crates, and it covers the whole engine:

- **Rendering** through a context: meshes, textures, glTF models, SDF text, lights and frames
  (`stickshift-render`, `stickshift-render-api`, `stickshift-assets`).
- **The engine** ([The engine](#the-engine)): an engine object that runs the game loop for a game
  written as C callbacks, with the engine's ECS world, scene streaming and floating origin,
  camera, input, audio and graphics settings (`stickshift-core`, `stickshift-ecs`,
  `stickshift-scene`, `stickshift-camera`, `stickshift-audio`). The host owns the window or view
  and drives the loop, one tick per display refresh.
- **Math** that gives the bits a Rust game gets (`stickshift-math`, glam).

A host may use the rendering half alone, as before, and draw everything itself.

- Header: [`stickshift.h`](../crates/stickshift-capi/include/stickshift.h), generated by cbindgen from
  `crates/stickshift-capi` (plain C11, usable from C++).
- Libraries: `libstickshift.a` and `libstickshift.dylib` (install name `@rpath/libstickshift.dylib`).

## Conventions

- **Names.** Functions are `stickshift_<module>_<verb>`. Types are `StickShift<Name>`. Constants are
  `STICKSHIFT_<NAME>`. Every enum-like type is a fixed-width integer `typedef` with `#define`
  constants, so any value a C caller passes is defined behaviour (an unknown value is rejected
  with `STICKSHIFT_ERROR_INVALID_ARGUMENT`).
- **Math.** Right-handed, Y up; a camera looks down −Z. `StickShiftMat4` is **column-major**
  (`m[0..3]` is the first column): sixteen floats, each column contiguous. Clip-space
  depth is Metal's `0..1`. Angles are radians unless a name says `_deg`.
- **Colour.** Linear RGB(A) floats in `0..1`. The engine tonemaps and encodes to sRGB on output.
- **2D overlay.** Pixel coordinates of the drawable, origin at the **top-left**, +y down.
- **Strings.** UTF-8, NUL-terminated. Strings passed in are copied before the call returns.
  Strings returned are owned by the library; each function says how long they stay valid.
- **Pointers.** Output pointers must be non-NULL unless documented as optional. Pointer
  arguments are only read during the call unless the docs say otherwise (`StickShiftData`, readback
  buffers).
- **Sized structs.** A struct whose first field is `uint32_t size` (after `api_version` where it
  has one) can grow: set `size = sizeof(TheStruct)`. An input is read for the bytes its `size`
  covers, and fields past it count as 0, meaning "default"; an output is written for its `size`
  and gets `size` set to the library's layout. A `size` below the first layout is
  `STICKSHIFT_ERROR_INVALID_ARGUMENT`. Plain value types (`StickShiftTransform`,
  `StickShiftStreamingConfig`, `StickShiftChase`, `StickShiftRenderComponent`,
  `StickShiftGraphicsSettings`) have no `size` field and never change.
- **Strides.** Arrays of structs that may grow cross with an explicit stride: host events going
  in; menu groups and items, recorded draws and quads coming out. Step through them by the stride,
  not by `sizeof`.

## Concepts

### Contexts

The API has two opaque objects a host creates and destroys: a context (`StickShiftContext *`) and
an engine attached to one ([The engine](#the-engine)). A context owns the Metal device, every
resource, the worker threads that load models, and the event queue. Create one per render target:

- **Layer context**: renders into a `CAMetalLayer` the host owns (from an `NSView`, a `UIView`
  in 0.2, or an `MTKView`'s layer). The engine sets the layer's `device`, `pixelFormat`
  (`BGRA8Unorm`) and `drawableSize`; the host keeps it in its view hierarchy and calls
  `stickshift_context_resize` when the view changes size.
- **Offscreen context**: `metal_layer = NULL`. Renders into a fixed-size texture whose pixels
  can be read back (`stickshift_frame_read_pixels_async`). Used for tests, thumbnails and tools.
- **Null backend**: `backend = STICKSHIFT_BACKEND_NULL`. No GPU at all: resources and frames are
  tracked, draws are counted, nothing is drawn, read-backs return zeros. It resizes like a layer
  context. For host-side unit tests, and for engines that run without a screen (tools, traces),
  on machines without a GPU. On non-Apple platforms it is the only backend.

A context is ready to render once `STICKSHIFT_EVENT_CONTEXT_READY` has been delivered. Before that,
resource creation is accepted (resources stay pending) and `stickshift_frame_acquire` returns
`STICKSHIFT_FRAME_SKIPPED`. In v0.1 the context is ready as soon as `stickshift_context_create`
returns, and the event is already queued.

### Handles and resource states

Everything a context owns, other than the context itself, is named by a **typed 64-bit handle**:

```c
typedef struct StickShiftMesh    { uint64_t id; } StickShiftMesh;
typedef struct StickShiftTexture { uint64_t id; } StickShiftTexture;
typedef struct StickShiftModel   { uint64_t id; } StickShiftModel;
typedef struct StickShiftFont    { uint64_t id; } StickShiftFont;
```

- `id == 0` is the null handle and never names a resource.
- An `id` encodes the handle kind, the issuing context, a slot index and a 24-bit generation. A
  handle is never reissued: once destroyed it stays invalid, and every later use returns
  `STICKSHIFT_ERROR_INVALID_HANDLE`. A slot whose generation would wrap is retired, not reused.
- Handles are only meaningful to the context that issued them. Every live context has a different
  context tag in its ids, so passing one context's handle to another returns
  `STICKSHIFT_ERROR_INVALID_HANDLE` (or `STICKSHIFT_RESOURCE_STATE_INVALID`).

Each resource is in one of these states (`stickshift_resource_state`):

| State | Meaning |
|---|---|
| `STICKSHIFT_RESOURCE_STATE_INVALID` | Not a live handle: never issued, destroyed, or another context's. |
| `STICKSHIFT_RESOURCE_STATE_PENDING` | Accepted; the work to make it usable has not finished. |
| `STICKSHIFT_RESOURCE_STATE_READY` | Usable in draws. |
| `STICKSHIFT_RESOURCE_STATE_FAILED` | The work failed. The handle stays valid (so you can read the state and destroy it) but draws using it are skipped. The failure event carries the reason. |

`*_create` and `*_load_*` calls return `STICKSHIFT_OK` and a handle **immediately**, with the resource
`PENDING` (or already `READY`, see the v0.1 table). They return an error only for problems they
can detect at once: a bad argument, a full handle table, a busy context.

Destroying a resource invalidates its handle at once. GPU memory is released only after every
submitted frame that used it has finished (command buffers retain what they reference).
Destroying a pending resource cancels its work and reports no event for it. A model's parse stops
at its next stage: after the file is read, after its buffers load, or before the next image decode
or mesh primitive. Its `StickShiftData` is still released, by the next `stickshift_poll_events`
or `stickshift_context_flush` once the parse has let go of it (see
[Data ownership](#data-ownership)).

### Events and completion callbacks

Completions are reported as `StickShiftEvent`s:

```c
typedef struct StickShiftEvent {
    StickShiftEventType kind;    // STICKSHIFT_EVENT_*
    StickShiftResult    result;  // STICKSHIFT_OK, or why it failed
    uint64_t       object;  // the handle id the event is about, or 0
    uint64_t       frame;   // the frame number the event is about, or 0
    const char    *message; // detail for failures, or NULL
} StickShiftEvent;
```

| Event | When |
|---|---|
| `STICKSHIFT_EVENT_CONTEXT_READY` | The context can render. |
| `STICKSHIFT_EVENT_RESOURCE_READY` | A mesh, texture, model or font became `READY` (`object`). |
| `STICKSHIFT_EVENT_RESOURCE_FAILED` | It became `FAILED`; `result` and `message` say why. |
| `STICKSHIFT_EVENT_FRAME_COMPLETED` | The GPU finished frame `frame`. Frames complete in submission order. |
| `STICKSHIFT_EVENT_READBACK_COMPLETE` | The pixels requested for frame `frame` are in the caller's buffer. |
| `STICKSHIFT_EVENT_READBACK_FAILED` | They will never arrive (the frame was skipped or discarded). |

Events are delivered in two ways, **always on a host thread that is inside a `stickshift_*` call,
never on an engine thread**:

1. **Polling.** `stickshift_poll_events` copies queued events into a caller array. It also does the
   context's housekeeping: it uploads finished model loads, notices finished GPU frames and
   copies finished read-backs. Call it once per frame (or whenever you like).
2. **Per-call callbacks.** Functions that start work take an optional
   `const StickShiftCompletion *` (`{ callback, user }`). If given, that work's event goes to `callback` instead of
   the poll queue (each event is delivered exactly once). Callbacks run inside
   `stickshift_poll_events`, `stickshift_context_flush` or, in v0.1, inside the call that started the
   work when it completes immediately.

`message` and the event pointer passed to a callback are valid until the callback returns
(callbacks) or until the next `stickshift_poll_events` on the context (polling). Callbacks may call
back into the same context, except `stickshift_context_destroy`. That includes
`stickshift_poll_events`: a poll delivers its callbacks before it copies any events, so a poll made
from a callback finishes first and never frees the messages the outer poll hands out.

### Data ownership

Bulk data (vertices, indices, pixels, model files) is passed as `StickShiftData`:

```c
typedef void (*StickShiftReleaseFn)(void *user, const void *ptr, size_t len);

typedef struct StickShiftData {
    const void     *ptr;
    size_t          len;      // bytes
    StickShiftReleaseFn  release;  // NULL: the engine copies the bytes before the call returns
    void           *user;
} StickShiftData;
```

- `release == NULL`: **copied**. The caller may free or reuse the buffer as soon as the call
  returns.
- `release != NULL`: **borrowed**, zero-copy. The bytes must stay valid and unchanged until the
  engine calls `release(user, ptr, len)`. It does so **exactly once**, from inside a `stickshift_*`
  call on the calling thread, after it no longer needs the bytes, and at the latest during
  `stickshift_context_destroy`.
- If the call that receives the data **fails**, the engine did not take it: `release` is not
  called and the caller still owns the buffer.

### Frames

A frame is recorded CPU-side and handed to the GPU as one unit:

```c
StickShiftFrame *frame;
if (stickshift_frame_acquire(ctx, &frame) == STICKSHIFT_OK) {
    stickshift_frame_set_camera(frame, &camera);
    stickshift_frame_draw_model(frame, car, &world, NULL);
    stickshift_frame_draw_text(frame, font, "Score 42", 16, 40, 24, white);
    stickshift_frame_submit(frame, NULL, &frame_number);
}
```

- `stickshift_frame_acquire` **never waits**. It returns `STICKSHIFT_FRAME_SKIPPED` when the GPU already
  has the maximum number of frames in flight (3), when the context is not ready yet, or when the
  drawable size is zero. Skip that tick's rendering and try again next tick. It returns
  `STICKSHIFT_ERROR_WRONG_STATE` if a frame is already open: one frame per context at a time.
- Recording calls (`stickshift_frame_draw_*`, `stickshift_frame_set_*`) only append to the frame. Nothing
  reaches Metal until `stickshift_frame_submit`.
- `stickshift_frame_submit` encodes and commits the frame and returns; it never waits for the GPU. It
  returns `STICKSHIFT_FRAME_SKIPPED` if the layer had no drawable to give (for example the window is
  hidden). Either way the frame is closed. `stickshift_frame_discard` closes it without rendering.
- **Camera and sun/sky are sticky**: they keep their last value across frames until set again.
  Within a frame, the last value set before submit applies to the whole frame (every draw, the
  sky and the shadow fit). Before the first set, the camera is the identity and the sun is
  `stickshift_sun_sky_default`.
- **Lights are per frame**: `stickshift_frame_add_light` adds a point or spot light to the open
  frame only, and the next frame starts with none. Every light added before submit lights every
  draw in the frame. A frame holds up to `STICKSHIFT_MAX_LIGHTS` (256); past that the call returns
  `STICKSHIFT_ERROR_LIMIT_EXCEEDED`. A light's brightness falls off with the inverse square of the
  distance and reaches exactly zero at its `range`, so keep ranges as short as the light needs: the
  renderer shades a light only where it reaches. If a frame's lights together cover more of the
  screen than the renderer's budget, it drops whole lights that no longer fit, so lights added
  earlier keep priority (see [ARCHITECTURE §4c](ARCHITECTURE.md#4c-point-and-spot-lights)).
- **Emission**: `StickShiftMaterial.emissive` is light a surface gives off itself (a lit window, a
  lamp's bulb), added after lighting. It lights nothing around it and costs nothing per light. A
  glTF model's parts take theirs from the material's `emissiveFactor`.
- 3D draws are depth-tested. 2D quads and text composite on top of the 3D scene, in record
  order.
- **Draws and handle states.** A draw naming a `PENDING` or `FAILED` resource is not recorded:
  the call returns `STICKSHIFT_NOT_READY` and counts it in `StickShiftStats.draws_skipped`. A destroyed or
  unknown handle returns `STICKSHIFT_ERROR_INVALID_HANDLE`. A resource destroyed after a draw was
  recorded, but before submit, is dropped from the frame at submit and counted the same way.
  `draws_skipped` counts draw *calls*: a dropped model or text draw counts once, however many
  parts or glyphs it recorded.
- **Materials.** Meshes with the `POS_NORMAL_UV` layout sample `base_color_texture` (white if
  none) and multiply it by `base_color`. Meshes with the `POS_NORMAL_COLOR` layout take their
  colour from the vertices; `base_color` and the texture are ignored for them in v0.1, so the
  texture handle is not checked and destroying it does not drop the draw.
- **Colour spaces.** Lighting is linear. Create colour images (photos, painted albedo) with
  `STICKSHIFT_COLOR_SPACE_SRGB`: the sampler decodes them to linear before shading. Create data
  (an SDF font atlas, masks) with `STICKSHIFT_COLOR_SPACE_LINEAR`: it is sampled as stored. Model
  textures are sRGB automatically. `STICKSHIFT_FILL_TEXTURE` quads show the colours a texture stores
  in either colour space; font atlases and `STICKSHIFT_FILL_SDF` textures must be linear, and an sRGB
  one is refused with `STICKSHIFT_ERROR_INVALID_ARGUMENT`.

Frame numbers start at 1 and increase by one per submitted frame. `STICKSHIFT_EVENT_FRAME_COMPLETED`
reports them in order.

### Threading

- A context, and the frame it hands out, may be used from **any thread, but by one thread at a
  time**. A call that overlaps another call on the same context returns `STICKSHIFT_ERROR_BUSY` at
  once and does nothing; it never waits for the other call and never corrupts state.
- Different contexts are independent and may be used from different threads at the same time.
- Thread-safe, callable from anywhere at any time: `stickshift_api_version`, `stickshift_version_string`,
  `stickshift_result_name`, `stickshift_last_error_message`, the math helpers (`stickshift_mat4_*`,
  `stickshift_quat_*`, `stickshift_vec3_*` and `stickshift_transform_to_mat4`),
  `stickshift_render_settings_default` and `stickshift_sun_sky_default`.
- Callbacks and `release` functions run on the thread that is inside the `stickshift_*` call that
  delivers them, never on an engine thread.
- **An engine is bound to one thread**: the one that created it. Every engine call, and every call
  on its context, from another thread returns `STICKSHIFT_ERROR_WRONG_THREAD` at once. Its hooks and
  callbacks run on that thread. See [Scopes and threads](#scopes-and-threads).

### Errors

Every fallible function returns a `StickShiftResult`. `STICKSHIFT_OK` (0) is success; small positive values
are non-error outcomes; negative values are errors:

| Code | Meaning |
|---|---|
| `STICKSHIFT_OK` | Done. |
| `STICKSHIFT_FRAME_SKIPPED` | No frame this time (see [Frames](#frames)). Not an error. |
| `STICKSHIFT_NOT_READY` | A resource the call needs is pending or failed; nothing was done. A tick held by `STICKSHIFT_ENGINE_HOLD_UNTIL_LOADED` returns it too. |
| `STICKSHIFT_ABSENT` | The entity is gone or lacks the component; nothing was done. Not an error. |
| `STICKSHIFT_ERROR_INVALID_ARGUMENT` | NULL where a pointer is required, a bad enum value, sizes that don't match. |
| `STICKSHIFT_ERROR_INVALID_HANDLE` | The handle is null, destroyed, of the wrong kind, or another context's. |
| `STICKSHIFT_ERROR_WRONG_STATE` | The call is not allowed now (no frame open, frame already open, …), including an engine call its scope does not allow ([Scopes and threads](#scopes-and-threads)). |
| `STICKSHIFT_ERROR_BUSY` | Another call on this context is in progress. |
| `STICKSHIFT_ERROR_NO_DEVICE` | No Metal device (or Metal is unavailable on this platform). |
| `STICKSHIFT_ERROR_UNSUPPORTED` | Not supported by this context or build (e.g. read-back on a layer context, header/library version mismatch). |
| `STICKSHIFT_ERROR_IO` | A file could not be read. |
| `STICKSHIFT_ERROR_PARSE` | A glTF or image could not be decoded. |
| `STICKSHIFT_ERROR_LIMIT_EXCEEDED` | An engine limit was hit (see [Limits](#limits)). |
| `STICKSHIFT_ERROR_INTERNAL` | A bug in the engine (a Rust panic caught at the boundary). The context may be inconsistent; destroy it. A panic in an engine call poisons only the engine: destroy it; its context stays usable. |
| `STICKSHIFT_ERROR_TIMEOUT` | A wait gave up before its work finished (a hung GPU, or a load that never completed). The work stays pending. |
| `STICKSHIFT_ERROR_WRONG_THREAD` | An engine call, or a call on a context with an engine attached, from a thread other than the engine's. |
| `STICKSHIFT_ERROR_ABORTED` | The game's init hook failed; the engine is failed. Destroy it. |

On any error the call has no effect, and `stickshift_last_error_message()` returns a description. That
message is per-thread and valid until the next failing call on the same thread. It is never NULL
(an empty string when there is none). `stickshift_result_name(code)` returns the constant's name.

No panic, abort or exception ever crosses the C boundary.

## The engine

A `StickShiftEngine *` runs Stick Shift Engine's own game loop for a game written as C callbacks.
It is the same Rust the engine's Rust games run: `stickshift-core`'s `drive_frame` and its
platform-free `Session`, which the windowed Rust runner also drives. Game state lives in the
engine's ECS world (hecs), its scene (streaming and the floating origin), its camera, input,
audio (kira) and graphics settings, and C reaches all of them through the functions below. The
game is game code only.

The host keeps the window or view and the display link. It **drives the loop**: it calls
`stickshift_engine_tick` once per display refresh and forwards the platform's events with
`stickshift_engine_push_events`. The engine decides how many fixed updates to run, runs them, and
renders. It never quits by itself and never touches the window: what only the host can do comes
back as request bits.

[`examples/c/engine.c`](../examples/c/engine.c) is a short, complete game on the engine:
streaming, the chase camera, a game component, queries, the floating origin and host events.

```c
static StickShiftResult init(void *user, StickShiftEngine *e)             { /* spawn, stream */ }
static void update(void *user, StickShiftEngine *e, float dt)             { /* move, query */ }
static void render(void *user, StickShiftEngine *e, StickShiftFrame *f)   { /* draw */ }

StickShiftGame game = {sizeof game, 0, &state, init, update, render, NULL, NULL};
StickShiftEngineDesc desc = {.api_version = STICKSHIFT_API_VERSION, .size = sizeof desc,
                             .audio = STICKSHIFT_AUDIO_DEVICE,
                             .flags = STICKSHIFT_ENGINE_PERSIST_SETTINGS};
StickShiftEngine *engine;
stickshift_engine_create(ctx, &desc, &game, &engine);   // a layer context
stickshift_engine_resume(engine, &view, &requests);      // the view appeared: runs init

// Each display refresh:
stickshift_engine_push_events(engine, events, n, sizeof events[0], &requests);
StickShiftTickDesc tick = {.size = sizeof tick, .clock = STICKSHIFT_CLOCK_ENGINE};
StickShiftTickResult result = {.size = sizeof result};
stickshift_engine_tick(engine, &tick, &result);          // updates, then one render
if ((requests | result.requests) & STICKSHIFT_REQUEST_EXIT) { /* close the window */ }

// At shutdown: the engine first, then its context.
stickshift_engine_destroy(engine);
stickshift_context_destroy(ctx);
```

### The engine and the host-driven loop

**Create.** `stickshift_engine_create(ctx, &desc, &game, &out)` attaches a new engine to `ctx`,
which must outlive it. A context has at most one engine, and none may be created while a frame is
open on it (`STICKSHIFT_ERROR_WRONG_STATE`). The calling thread becomes the engine's thread. No
hook runs yet. While an engine is attached, `stickshift_context_destroy` is
`STICKSHIFT_ERROR_WRONG_STATE`.

```c
typedef struct StickShiftEngineDesc {
    uint32_t api_version;          // STICKSHIFT_API_VERSION
    uint32_t size;                 // sizeof(StickShiftEngineDesc)
    StickShiftAudioOutput audio;   // STICKSHIFT_AUDIO_SILENT (tools, tests) or _DEVICE
    StickShiftFramePacing pacing;  // STICKSHIFT_FRAME_PACING_WAIT (default) or _SKIP
    uint32_t flags;                // STICKSHIFT_ENGINE_* bits
    uint32_t reserved;             // 0
    const char *settings_suite;    // with PERSIST_SETTINGS: NULL (standard defaults) or a suite name
} StickShiftEngineDesc;
```

| Flag | |
|---|---|
| `STICKSHIFT_ENGINE_PERSIST_SETTINGS` | Restore the player's graphics settings at create and save every change ([Menu and persistence](#menu-and-persistence)). |
| `STICKSHIFT_ENGINE_QUIT_ON_ESCAPE` | An Escape key-down returns `STICKSHIFT_REQUEST_EXIT` (the game still sees the key). |
| `STICKSHIFT_ENGINE_HOLD_UNTIL_LOADED` | After init, a tick runs no update or render while a model of the context is still loading. It returns `STICKSHIFT_NOT_READY` with `held` set and banks no time, and the first tick after the hold banks one step. For hosts that load asynchronously. |

| Pacing | |
|---|---|
| `STICKSHIFT_FRAME_PACING_WAIT` | Before the render hook, wait (at most a second) for a free frame slot, as the Rust runner blocks on its drawable. Every frame is rendered and submitted. Tools and recorders use this. |
| `STICKSHIFT_FRAME_PACING_SKIP` | Never wait. With no free slot the render hook still runs, into a frame the engine then discards and counts (`frames_discarded`). |

**Start.** One of:

- `stickshift_engine_resume(engine, &view, &requests)` when the view appears (and again each time
  it reappears). The first call sets the camera's aspect to the view's (`width / max(height, 1)`).
  Every call sizes the drawable for the view at the render scale in effect, runs the game's init
  hook if it has not run, sizes the drawable again for the settings init left, and records the
  safe area. It returns `STICKSHIFT_REQUEST_MENU_SYNC`. The engine is now *hosted*. A Metal
  offscreen context keeps its size.
- `stickshift_engine_init(engine)` for an engine with no view: tools, tests and headless runs.
  Idempotent.

Either way, init happens once in the engine's life: queued settings (a restore, or a request made
before init) become current, then the init hook runs, then the streaming reach the hook set up is
recorded as the base the draw distance scales, and the render settings reach the context.

**Tick.** `stickshift_engine_tick(engine, &tick, &result)` is one display frame:

1. **Housekeeping**, as `stickshift_poll_events` does: finished model loads are uploaded, finished
   frames and read-backs are noticed, and their callbacks run. A frame the host left open on the
   context is `STICKSHIFT_ERROR_WRONG_STATE`.
2. **The load hold**, with `STICKSHIFT_ENGINE_HOLD_UNTIL_LOADED`.
3. **Settings.** A settings change queued last frame is applied: the renderer and the streaming
   reach get it, then the game's settings hook runs. The engine then resizes the drawable for the
   new render scale (once a view is reported), saves the settings (with `PERSIST_SETTINGS`) and
   raises `STICKSHIFT_REQUEST_MENU_SYNC`. All of this happens before the frame, so no frame renders
   new settings at the old size. An engine with no view runs the same step with nothing to resize.
4. **The clock** is read (below), and the time banked in the fixed-step accumulator.
5. **Updates**: 0 to `STICKSHIFT_MAX_STEPS_PER_FRAME` (5) update hooks, each with
   `dt = stickshift_fixed_dt()`. Time past five steps is dropped, so a stall slows the game
   instead of wedging it. Input edges clear after each update.
6. **The camera push**: the engine camera becomes the context's sticky camera.
7. **Render**: under `WAIT` pacing, the wait for a free frame slot; then the engine opens the
   context's frame, runs the render hook with it, and submits it (or discards it, under `SKIP` with
   no slot). The render hook runs exactly once in every tick that is not held.

`result` (optional) says what the tick did:

```c
typedef struct StickShiftTickResult {
    uint32_t size;               // sizeof(StickShiftTickResult)
    uint32_t steps;              // update hooks run
    uint8_t  rendered;           // 1 if the render hook ran
    uint8_t  submitted;          // 1 if the frame went to the GPU
    uint8_t  readback_ready;     // 1 if tick->readback holds this frame
    uint8_t  held;               // 1 if HOLD_UNTIL_LOADED held the tick
    uint32_t requests;           // STICKSHIFT_REQUEST_* bits
    uint64_t frame;              // the submitted frame's number, or 0
    uint64_t graphics_revision;  // how many settings changes have been applied
} StickShiftTickResult;
```

| Clock (`tick->clock`) | Elapsed time the tick banks |
|---|---|
| `STICKSHIFT_CLOCK_FIXED_STEP` | Exactly `STICKSHIFT_FIXED_DT_NS` (16 666 666 ns): one update per tick. Tools, tests and traces, which then match the Rust headless driver frame for frame. |
| `STICKSHIFT_CLOCK_ELAPSED` | `tick->nanoseconds`. |
| `STICKSHIFT_CLOCK_TIMESTAMP` | The time since the last timestamp tick, where `tick->nanoseconds` is the host's monotonic clock now (`CLOCK_UPTIME_RAW` on Apple platforms), saturating at 0. |
| `STICKSHIFT_CLOCK_ENGINE` | As `TIMESTAMP`, with the engine reading the monotonic clock itself after the settings step, where the Rust runner reads it. A view host uses this. |

Times cross as integer nanoseconds, never as a rounded `double`. The first `TIMESTAMP` or `ENGINE`
tick, and the first after a menu choice, a held tick or `stickshift_engine_reset_clock`, banks
exactly one fixed step, so a pause (an app returning to the foreground, a modal sheet) is not
simulated in one burst.

**Requests** are what only the host can do, returned by ticks, `resume` and `push_events`:

| Bit | The host should |
|---|---|
| `STICKSHIFT_REQUEST_EXIT` | Close the view and stop ticking: the view was closed, Escape was pressed with `QUIT_ON_ESCAPE`, or the game called `stickshift_engine_request_exit` (every later tick reports it again). |
| `STICKSHIFT_REQUEST_TOGGLE_FULLSCREEN` | Enter or leave full screen: the menu's full-screen item was chosen. |
| `STICKSHIFT_REQUEST_MENU_SYNC` | Refresh its native Graphics menu: the settings or the full-screen title may have changed. |

**Read-back.** On an offscreen context with `WAIT` pacing, `tick->readback` (`width × height × 4`
bytes, BGRA8, top row first, `tick->readback_len` long) receives the tick's frame before the call
returns, waiting up to ten seconds for the GPU; `result.readback_ready` says it arrived. Elsewhere
a read-back is `STICKSHIFT_ERROR_UNSUPPORTED`, and a short buffer `INVALID_ARGUMENT`. A recorder
ticks with `CLOCK_FIXED_STEP` and reads every frame this way.

**The engine's frame.** During a tick the engine owns the context's one open frame: the render
hook draws into it with the usual `stickshift_frame_draw_*` calls, and must not submit or discard
it (`STICKSHIFT_ERROR_WRONG_STATE`), and `stickshift_frame_acquire` is `WRONG_STATE` inside every
engine call. Engine frames complete internally and queue no `STICKSHIFT_EVENT_FRAME_COMPLETED`.
Between ticks the host may still acquire, record and submit a frame of its own on the context, as
long as it is closed before the next tick. After each tick, `stickshift_context_get_last_frame`
reads what the frame recorded ([Inspection](#inspection)).

**State.** `stickshift_engine_get_state` reads the engine's flags and counters:

```c
typedef struct StickShiftEngineState {
    uint32_t size;                               // sizeof(StickShiftEngineState)
    uint8_t  initialized, hosted, failed, poisoned, exit_requested, holding;
    uint8_t  reserved[2];
    uint64_t frames, updates, frames_rendered, frames_discarded;
} StickShiftEngineState;
```

`stickshift_engine_get_perf` reads frame timing (`StickShiftPerf`: frames per second, frame, CPU,
GPU and render-hook times, and, in the render hook, the interpolation `alpha` between the last two
updates).

**Failure.** If the init hook returns a negative result, `stickshift_engine_init` or `_resume`
returns `STICKSHIFT_ERROR_ABORTED` and the engine is *failed*: every later `init`, `resume` and
`tick` is `STICKSHIFT_ERROR_WRONG_STATE`. If a panic (a bug in the engine) is caught in any engine
call, the engine is *poisoned*: every later call that takes the engine (`stickshift_engine_*`,
`_component_*`, `_world_*`, `_scene_*`, `_stream_*`, `_camera_*`, `_input_*`, `_audio_*`,
`_graphics_*`) returns `STICKSHIFT_ERROR_INTERNAL`, except `stickshift_engine_get_state`, which
still answers with `poisoned` set, and `stickshift_engine_destroy`. Calls on its context and frames
are not refused. Destroy a failed or poisoned engine; its context stays usable.

**Destroy.** `stickshift_engine_destroy` calls the game's `release` hook exactly once, detaches the
context and drops the loop, which stops the audio device. It works on a failed or poisoned engine.
Destroy the engine before its context.

| Function | Scope ([rules](#scopes-and-threads)) | |
|---|---|---|
| `stickshift_engine_create(ctx, desc, game, out)` | any thread | Attach an engine to `ctx`. |
| `stickshift_engine_destroy(engine)` | host | Release the game, detach, stop audio. NULL is a no-op. |
| `stickshift_engine_get_context(engine, out)` | any | The attached context, borrowed. |
| `stickshift_engine_init(engine)` | host | Run init with no view. |
| `stickshift_engine_resume(engine, view, out_requests)` | host | The view appeared; runs init once. |
| `stickshift_engine_tick(engine, tick, out)` | host | One display frame. |
| `stickshift_engine_push_events(engine, events, count, stride, out_requests)` | host | Apply host events ([Input and host events](#input-and-host-events)). |
| `stickshift_engine_reset_clock(engine)` | host | The next timestamp tick banks one step. |
| `stickshift_engine_request_exit(engine)` | game | Every later tick reports `REQUEST_EXIT`. |
| `stickshift_engine_get_state(engine, out)` | game | Flags and counters; answers when poisoned. |
| `stickshift_engine_get_perf(engine, out)` | game | Frame timing. |
| `float stickshift_fixed_dt(void)` | thread-safe | The fixed step in seconds: the `f32` nearest 1/60 (bits `0x3C888889`). |

### Game hooks

```c
typedef struct StickShiftGame {
    uint32_t size;                                       // sizeof(StickShiftGame)
    uint32_t reserved;                                   // 0
    void *user;                                          // passed to every hook; borrowed until release
    StickShiftGameInitFn init;                           // required
    StickShiftGameUpdateFn update;                       // required
    StickShiftGameRenderFn render;                       // required
    StickShiftGameSettingsFn graphics_settings_changed;  // optional
    StickShiftGameReleaseFn release;                     // optional
} StickShiftGame;
```

| Hook | Runs | |
|---|---|---|
| `StickShiftResult init(void *user, StickShiftEngine *engine)` | Once, inside `stickshift_engine_init` or the first `_resume`, before any update. | Set up the world, the scene, the camera, sounds and models. A negative result fails the engine. It may block on a model with `stickshift_model_wait`, as a Rust game's synchronous `AssetCache::load` does. |
| `void update(void *user, StickShiftEngine *engine, float dt)` | 0 to 5 times per tick. | `dt` is always `stickshift_fixed_dt()`. |
| `void render(void *user, StickShiftEngine *engine, StickShiftFrame *frame)` | Once per tick, after the tick's updates. | Draws into the open `frame`. The world and the scene are read only here. |
| `void graphics_settings_changed(void *user, StickShiftEngine *engine, const StickShiftGraphicsSettings *settings)` | After a settings change reaches the renderer and the scene: inside a tick's settings step, or inside `push_events` for a menu choice. | Not for a restore. |
| `void release(void *user)` | Once, inside `stickshift_engine_destroy`. | Free `user`. The engine can no longer be used. |

The struct is copied at create. The hooks run on the engine's thread, inside the engine call that
runs them, and must not unwind across the boundary (no C++ exception may escape a
hook). A hook makes its engine calls with the `engine` pointer it is given.

### Scopes and threads

Every engine function takes the engine pointer, and what a call may do depends on where it is made
from. This is Rust's borrow structure, checked at run time: during a tick the loop holds the
engine's state, so a hook reaches it only through the context the loop passed that hook, and a
stream pass lends its spawn callback the world and nothing else. A call the current scope does not
allow returns **`STICKSHIFT_ERROR_WRONG_STATE`** and does nothing; the engine stays usable.

| Calls | Between engine calls | `init`, `update` and settings hooks | Render hook | Spawn callback | Outside hooks |
|---|---|---|---|---|---|
| **Host**: `stickshift_engine_init`, `_resume`, `_tick`, `_push_events`, `_reset_clock`, `_destroy`, `stickshift_graphics_get_state`, `stickshift_engine_get_menu`; and `stickshift_frame_acquire` on the engine's context | yes | `WRONG_STATE` | `WRONG_STATE` | `WRONG_STATE` | `WRONG_STATE` |
| **Game**: `stickshift_engine_get_state`, `_get_perf`, `_request_exit`, `stickshift_camera_*`, `stickshift_input_get`, `stickshift_audio_*`, `stickshift_graphics_get_current`, `_request` | yes | yes | yes | `WRONG_STATE` | `WRONG_STATE` |
| **Scene reads**: `stickshift_scene_get_config`, `_streamed_count` | yes | yes | yes | `WRONG_STATE` | `WRONG_STATE` |
| **Scene changes**: `stickshift_scene_set_config`, `_stream`, `_maybe_rebase` | yes | yes | `WRONG_STATE` | `WRONG_STATE` | `WRONG_STATE` |
| **World reads**: `stickshift_world_get`, `_has`, `_contains`, `_len`, `_query`, `_query_count` | yes | yes | yes | yes | `WRONG_STATE` |
| **World changes**: `stickshift_world_spawn`, `_despawn`, `_set`, `_insert`, `_remove` | yes | yes | `WRONG_STATE` | yes | `WRONG_STATE` |
| **Tracking**: `stickshift_stream_track` | `WRONG_STATE` | `WRONG_STATE` | `WRONG_STATE` | yes | `WRONG_STATE` |
| **Any scope**: `stickshift_engine_get_context`, `stickshift_component_register`, `_get_desc`, `stickshift_world_query_release` | yes | yes | yes | yes | yes |

- *Outside hooks* is a callback the engine delivers inside an engine call but outside every hook:
  a completion that a tick's housekeeping delivers, and the release hook. (A completion that
  `stickshift_model_wait` delivers inside a hook is in that hook's scope.)
- **Context calls** keep their own rules ([Threading](#threading)) with an engine attached, plus
  these: `stickshift_context_destroy` is `WRONG_STATE` while the engine exists, the render hook's
  frame cannot be submitted or discarded, and no frame can be acquired inside an engine call.
- **The camera push.** Inside a hook, the first context or frame call after the game moved the
  camera pushes the moved camera to the context first, as Rust's `EngineCtx::renderer` does, so a
  draw always sees the camera the game set. A spawn callback never pushes.
- **One thread.** An engine, and the context it is attached to, are used only on the thread that
  created the engine. A call from any other thread returns **`STICKSHIFT_ERROR_WRONG_THREAD`**
  before it touches anything: every engine call, and every context or frame call on that context.
  The thread-safe functions ([Threading](#threading)) stay callable anywhere.
- **Poisoned** engines answer `STICKSHIFT_ERROR_INTERNAL` to every engine call except
  `stickshift_engine_get_state` and `stickshift_engine_destroy`; calls on the context still work
  ([Failure](#the-engine-and-the-host-driven-loop)).

`crates/stickshift-capi/tests/engine.rs` checks this table for every function that takes an
engine, in every scope.

### Components and the world

**Entities** are `StickShiftEntity { uint64_t bits; }`, hecs's own `Entity::to_bits`
(`generation << 32 | id`); 0 is the null entity. Ids are reused last-freed first with a bumped
generation, so a stale entity reads as gone, never as another entity. Unlike resource handles, an
entity carries no context tag: it is meaningful only to the engine that issued it.

**Components** are `StickShiftComponent { uint32_t id; }`. The engine's own components have fixed
ids and keep their Rust types, so the scene's streaming and rebase see what C wrote:

| Id | Component | Value |
|---|---|---|
| `STICKSHIFT_COMPONENT_TRANSFORM` (1) | `TransformComponent` | `StickShiftTransform { position, rotation, scale }` |
| `STICKSHIFT_COMPONENT_RENDER` (2) | `RenderComponent` | `StickShiftRenderComponent { color[3], shape }` |
| `STICKSHIFT_COMPONENT_STATIC_TAG` (3) | `StaticTag` | none (a tag) |
| `STICKSHIFT_COMPONENT_DYNAMIC_TAG` (4) | `DynamicTag` | none (a tag) |

Ids 5..255 are reserved for engine components. A game registers its own with
`stickshift_component_register(engine, &desc, &out)`, where `desc` is
`{ const char *name; uint32_t size; uint32_t align; }`: a unique UTF-8 name, a value size of 0 (a
tag) up to `STICKSHIFT_MAX_COMPONENT_SIZE` (4096), and a power-of-two alignment up to 16. Ids start
at `STICKSHIFT_FIRST_GAME_COMPONENT` (256). Registering the same name, size and alignment again
returns the same component; the same name with another size or alignment is
`STICKSHIFT_ERROR_INVALID_ARGUMENT`; past `STICKSHIFT_MAX_GAME_COMPONENTS` (128) it is
`STICKSHIFT_ERROR_LIMIT_EXCEEDED`. Registering never changes the world, so it works in any scope,
and when a component is registered never changes any order. Each registered component gets a Rust
type of its own, so the world partitions entities into archetypes exactly as it does for a Rust
game's types.

A render component's `shape` is `STICKSHIFT_RENDER_SHAPE_CUBE` or `_SPHERE`, the meshes
`RenderComponent::cube` and `::sphere` build for the colour. Reading one whose mesh was made in
Rust gives `STICKSHIFT_RENDER_SHAPE_MESH`; writing `MESH` is `STICKSHIFT_ERROR_INVALID_ARGUMENT`.
The engine stores the component for the world's sake; drawing it is the game's render pass.

**Bundles.** Spawning and inserting take whole bundles of `StickShiftComponentValue`s:

```c
typedef struct StickShiftComponentValue {
    StickShiftComponent component;
    const void *data;   // `size` bytes, copied during the call; NULL for a tag
    uint32_t size;      // the registered size (sizeof the C struct for an engine component); 0 for a tag
} StickShiftComponentValue;
```

A bundle holds up to `STICKSHIFT_MAX_BUNDLE` (32) values in any order, each component once. Every
value is checked before anything changes.

| Function | |
|---|---|
| `stickshift_world_spawn(engine, values, count, out)` | One entity with the whole bundle, in one hecs spawn: it lands in the archetype a Rust tuple of the same components does. In a spawn callback it spawns into the stream pass's world. |
| `stickshift_world_despawn(engine, entity, out_existed)` | Despawn (its row is swap-removed, as in hecs). A gone entity is `OK` with `*out_existed = 0`; `out_existed` is optional. |
| `stickshift_world_contains(engine, entity, out)` | Whether it is alive. |
| `stickshift_world_has(engine, entity, component, out)` | Whether it has the component; 0 for a gone entity. |
| `stickshift_world_get(engine, entity, component, out, size)` | Copy the value (`size` = the registered size). A tag has no value (`INVALID_ARGUMENT`). |
| `stickshift_world_set(engine, entity, component, data, size)` | Overwrite the value in place; the entity does not move. |
| `stickshift_world_insert(engine, entity, values, count)` | Add the bundle, replacing values it already has, in one hecs insert. Unless its set of components is unchanged, the entity moves to the end of its new archetype, as in Rust. |
| `stickshift_world_remove(engine, entity, component)` | Remove one component (hecs `remove_one`), which moves the entity as in Rust. |
| `stickshift_world_len(engine, out)` | Live entities. |
| `stickshift_component_get_desc(engine, component, out)` | A component's name (library-owned, valid for the engine's life), size and alignment, engine components included. |

`get`, `set`, `insert` and `remove` return **`STICKSHIFT_ABSENT`** (a non-error, 3) when the entity
is gone or lacks the component, and change nothing.

### Queries

`stickshift_world_query(engine, terms, term_count, &rows)` snapshots the entities matching up to
`STICKSHIFT_MAX_QUERY_TERMS` (16) terms, in the world's own query order (archetypes in creation
order, then rows in order, as hecs iterates), with their values copied into engine-owned rows:

| Access (`StickShiftQueryTerm.access`) | |
|---|---|
| `STICKSHIFT_QUERY_READ` | Required, with the value in each row (for a tag, the same as `WITH`). |
| `STICKSHIFT_QUERY_WITH` | Required, no value. |
| `STICKSHIFT_QUERY_WITHOUT` | Excluded. At least one term must be something else. |
| `STICKSHIFT_QUERY_OPTIONAL` | Not a filter: the value when the entity has it, and a presence flag. |

```c
typedef struct StickShiftQueryRows {
    uint32_t size;                        // sizeof(StickShiftQueryRows), set by the caller
    uint32_t count;                       // matching entities
    const StickShiftEntity *entities;     // count entities, in query order
    const uint8_t *data;                  // count rows of `stride` bytes, starting 16-byte aligned
    size_t stride;
    const uint32_t *offsets;              // per term: its value's offset in a row, or UINT32_MAX
    const uint8_t *present;               // count * term_count flags, row by row
    uint32_t term_count;
    uint32_t reserved;
    uint64_t token;                       // for stickshift_world_query_release; never 0
} StickShiftQueryRows;

// Term k's value in row i (aligned for its component):
memcpy(&value, rows.data + i * rows.stride + rows.offsets[k], sizeof value);
```

An absent optional term's bytes are zero. Nothing stays borrowed from the world, so the caller may
change the world while walking the rows, and a hook may nest queries. A snapshot stays valid until
`stickshift_world_query_release(engine, token)`, until the hook or callback that took it returns,
or, if it was taken between engine calls, until the next tick; at most `STICKSHIFT_MAX_LIVE_QUERIES`
(16) are live at once (`STICKSHIFT_ERROR_LIMIT_EXCEEDED`). Releasing a token that is not live is
`INVALID_ARGUMENT`. `stickshift_world_query_count` counts the matches without copying anything.

### Scene: streaming and the floating origin

The scene streams entities along a travel axis, in slots a fixed distance apart, and keeps
coordinates small by rebasing the origin. Its configuration is a frozen value type:

```c
typedef struct StickShiftStreamingConfig {
    StickShiftVec3 axis;        // the travel axis; (0, 0, -1)
    float spawn_interval;       // between slots; 6
    float spawn_ahead;          // how far ahead slots are filled; 60
    float despawn_behind;       // how far behind streamed entities are despawned; 12
    float rebase_threshold;     // how far the focus may travel before a rebase; 1000
} StickShiftStreamingConfig;
```

| Function | |
|---|---|
| `void stickshift_streaming_config_default(StickShiftStreamingConfig *out)` | The defaults above. Thread-safe. |
| `stickshift_scene_get_config(engine, out)` | A copy. After init, `spawn_ahead` is the base reach scaled for the draw distance. |
| `stickshift_scene_set_config(engine, config)` | Replace it. Once streaming has started, changing `axis` or `spawn_interval` is `WRONG_STATE` and changes nothing. |
| `stickshift_scene_stream(engine, focus, spawn, user)` | One pass for `focus`: the tracked entities that fell behind are despawned, in the order they were tracked, then `spawn(user, engine, slot, position)` runs once per new slot, in slot order, inside the pass. `spawn` may be NULL (the frontier still advances). |
| `stickshift_stream_track(engine, entity)` | In a spawn callback: track `entity` for despawning behind (one with no transform at the slot's distance). |
| `stickshift_scene_maybe_rebase(engine, focus, out_offset)` | If `focus` passed the threshold, shift every transform component by one offset, and write it (else zero). |
| `stickshift_scene_streamed_count(engine, out)` | Tracked entities. |

A focus that is not finite is `INVALID_ARGUMENT` for `stream` and `maybe_rebase`. A spawn
callback reaches only the world and tracking ([Scopes and threads](#scopes-and-threads)). A rebase
moves transform components only: the camera, and anything else the game keeps in world
coordinates, are the game's to shift by the same offset:

```c
StickShiftVec3 offset;
stickshift_scene_maybe_rebase(engine, player, &offset);
if (offset.x != 0 || offset.y != 0 || offset.z != 0) {
    StickShiftCameraState cam = {.size = sizeof cam};
    stickshift_camera_get(engine, &cam);
    stickshift_camera_set_position(engine, (StickShiftVec3){cam.position.x + offset.x,
                                                            cam.position.y + offset.y,
                                                            cam.position.z + offset.z});
    /* ...and the target */
}
```

### Camera and chase

The engine owns one camera. `stickshift_camera_get(engine, &state)` reads its pose (`position`,
`target`, `up`), its lens (`fov_y`, 45° by default; `aspect_ratio`; `near_plane`, `far_plane`) and
the matrices they give now (`view`, `projection`, `view_projection`, with `forward` and `right`).
Each setter stores what it is given, as `stickshift-camera` does:

| Function | |
|---|---|
| `stickshift_camera_get(engine, out)` | Set `out->size = sizeof(StickShiftCameraState)`. |
| `stickshift_camera_set_position`, `_set_target`, `_set_up` | The pose. |
| `stickshift_camera_set_aspect_ratio`, `_set_fov_y` | Stored as given. A view's resize sets the aspect too. |
| `stickshift_camera_set_clip_planes(engine, near, far)` | Planes that are not finite, not positive or not `far > near` are ignored, as in Rust; `OK` either way. |
| `stickshift_camera_follow(engine, chase, target, forward, dt)` | The engine's chase controller, built from `*chase`: trail the target facing `forward` (zero counts as `-Z`), easing with the half-life or snapping without one. |
| `void stickshift_chase_init(StickShiftChase *out, float distance, float height)` | A chase with no look-at height, `+Y` up and no smoothing. Thread-safe. |

```c
typedef struct StickShiftChase {    // a frozen value type
    float distance;                 // behind the target, along its facing
    float height;                   // above it, along `up`
    float look_at_height;           // above it, where the camera aims
    StickShiftVec3 up;              // normalised when used; zero or non-finite means +Y
    float half_life;                // seconds to close half the gap; 0 snaps
} StickShiftChase;
```

The camera reaches the renderer as Rust's does: every tick pushes it to the context's sticky
camera before the render hook, and inside a hook the next context or frame call after a camera
write pushes it first ([Scopes and threads](#scopes-and-threads)). The render hook may still set a
frame's camera itself with `stickshift_frame_set_camera`; the next push replaces it.

### Input and host events

`stickshift_engine_push_events(engine, events, count, stride, &requests)` applies the platform's
events between ticks, in array order. `stride` is the distance between events, at least
`sizeof(StickShiftHostEvent)` (64 bytes), so the struct can grow. Every event is checked first, and
none is applied if one is invalid.

| Kind | Fields | Effect |
|---|---|---|
| `STICKSHIFT_HOST_KEY_DOWN` | `code` (`STICKSHIFT_KEY_*`), `flags` (`STICKSHIFT_HOST_EVENT_REPEAT`) | The key is held. A press of a key already held (an auto-repeat) makes no edge. Escape with `QUIT_ON_ESCAPE` also returns `REQUEST_EXIT`. |
| `STICKSHIFT_HOST_KEY_UP` | `code` | Released. |
| `STICKSHIFT_HOST_MOUSE_DOWN`, `_MOUSE_UP` | `code` (`STICKSHIFT_MOUSE_*`) | A button held or released. |
| `STICKSHIFT_HOST_CURSOR` | `x`, `y` | The cursor, in points from the view's top-left. |
| `STICKSHIFT_HOST_FOCUS_LOST` | | Every key and button is released. |
| `STICKSHIFT_HOST_VIEW_RESIZED` | `width`, `height` (physical pixels), `scale_factor` | The camera's aspect follows, the drawable is resized for the render scale; `REQUEST_MENU_SYNC`. |
| `STICKSHIFT_HOST_SCALE_CHANGED` | the same | The view moved to a display of another density: the drawable is resized, the aspect is left alone. |
| `STICKSHIFT_HOST_SAFE_AREA` | `insets` (points: top, right, bottom, left) | Kept, and converted to drawable pixels at each resize (`stickshift_context_get_safe_area`). |
| `STICKSHIFT_HOST_MENU` | `code` (a menu item's tag) | A Graphics menu choice ([Menu and persistence](#menu-and-persistence)). May run the settings hook inside this call. |
| `STICKSHIFT_HOST_CLOSE` | | `REQUEST_EXIT`. |

Keys are named by physical position: `STICKSHIFT_KEY_W`, `_A`, `_S`, `_D`, `_Q`, `_E`, `_LEFT`,
`_RIGHT`, `_UP`, `_DOWN`, `_SPACE`, `_ESCAPE`; mouse buttons are `STICKSHIFT_MOUSE_LEFT`, `_RIGHT`,
`_MIDDLE`. The host maps its platform's key codes to them; a key the engine does not name is not
sent. Both lists are append-only.

The game reads input with `stickshift_input_get(engine, &state)`:

```c
typedef struct StickShiftInputState {
    uint32_t size;               // sizeof(StickShiftInputState)
    uint8_t  keys[32];           // per STICKSHIFT_KEY_*: STICKSHIFT_KEY_STATE_DOWN | _JUST_PRESSED | _JUST_RELEASED
    uint8_t  mouse_buttons[8];   // per STICKSHIFT_MOUSE_*: 1 while held
    uint8_t  has_cursor;
    uint8_t  reserved[3];
    double   cursor_x, cursor_y; // points from the view's top-left
} StickShiftInputState;
```

Edges (`JUST_PRESSED`, `JUST_RELEASED`) clear only after each update, never per event or per tick:
a tap between two ticks reaches the next update, and a tick that runs no update keeps its edges for
the next one.

### Audio

`desc.audio` picks where sound goes: `STICKSHIFT_AUDIO_SILENT` (the default, for tools and tests)
accepts and counts every call and plays nothing; `STICKSHIFT_AUDIO_DEVICE` plays to the default
output device, or falls back to silent, with one line on stderr, when there is none. Either way no
audio call fails for want of a device.

Sounds are `StickShiftSound { uint64_t id; }` handles of the engine that loaded them, valid until
it is destroyed (sounds are never unloaded); another engine's sound is
`STICKSHIFT_ERROR_INVALID_HANDLE`. Levels are decibels: `STICKSHIFT_VOLUME_UNCHANGED_DB` (0) is the
recorded level, `STICKSHIFT_VOLUME_SILENT_DB` (−60) and below are inaudible.

| Function | |
|---|---|
| `stickshift_audio_load(engine, path, out)` | Decode the file at `path` now, once per path: loading it again returns the same sound. A file that cannot be read or decoded gives a silent sound and a line on stderr, as in Rust, so this fails only for a NULL or non-UTF-8 path. Silent engines decode nothing. |
| `stickshift_audio_play_once(engine, sound, volume_db)` | Play once, over whatever else plays. Counted even when nothing is heard. |
| `stickshift_audio_play_looping(engine, sound, volume_db)` | Loop on the single loop channel, replacing what loops now. Asking for the sound already looping does nothing. |

### Graphics settings

The player-facing settings are a frozen value type with reserved slots:

typedef struct StickShiftGraphicsSettings {
    StickShiftShadowQuality  shadows;          // STICKSHIFT_SHADOW_QUALITY_OFF / _LOW / _HIGH (default)
    StickShiftShadowDistance shadow_distance;  // STICKSHIFT_SHADOW_DISTANCE_MATCH_DRAW_DISTANCE (default) / _MEDIUM / _NEAR

`stickshift_graphics_request(engine, &settings)` queues new settings; the next tick's settings

made current by init, with no settings hook. Requests before then collapse to the last, and one
equal to the settings in effect changes nothing. An applied change gives the context its render
settings, scales the streaming reach (`spawn_ahead`) from the base init left, runs the settings
hook, resizes the drawable for the render scale (once a view is reported), is saved with
`PERSIST_SETTINGS`, raises
`REQUEST_MENU_SYNC` and bumps the revision.

### Menu and persistence

The engine's Graphics menu is data, so each host builds its native menu (an `NSMenu`, a `UIMenu`)
from the same model the Rust runner's AppKit menu uses. `stickshift_engine_get_menu(engine,
fullscreen, &menu)` (between engine calls) returns its title, then four submenus (shadows, shadow
distance, draw distance, render scale) and, after a separator, two actions (enter or exit full
screen, titled by `fullscreen`; reset to defaults). Groups and items cross with strides:

```c
StickShiftMenu menu = {.size = sizeof menu};
stickshift_engine_get_menu(engine, is_fullscreen, &menu);
for (uint32_t g = 0; g < menu.group_count; g++) {
    const StickShiftMenuGroup *group = (const void *)((const char *)menu.groups + g * menu.group_stride);
    // group->title is NULL for the actions after the separator
    for (uint32_t i = 0; i < group->item_count; i++) {
        const StickShiftMenuItem *item = (const void *)((const char *)group->items + i * group->item_stride);
        // item->tag, item->label, item->checked, item->enabled
    }
}
```

The menu is engine-owned and valid until the next `get_menu` or the engine's destroy. An item's
tag is `section × 100 + index` (from 1); the actions are 901 (full screen) and 902 (reset, enabled
when the settings differ from the defaults). Rebuild or re-check the native menu whenever a call
returns `STICKSHIFT_REQUEST_MENU_SYNC`.

A choice goes back as a `STICKSHIFT_HOST_MENU` event whose `code` is the item's tag. A settings
item builds on the request still queued, or else on the settings in effect, so two quick choices
compose, and applies at once, between ticks, by the same path a game's request takes (the settings
hook runs inside `push_events`). Before init the choice stays queued, and is saved at once. The
full-screen item changes nothing in the engine and returns `REQUEST_TOGGLE_FULLSCREEN`. Every
choice restarts the frame clock, since the platform's menu tracking held the thread while the menu
was open.

**Persistence.** With `STICKSHIFT_ENGINE_PERSIST_SETTINGS`, the engine restores the settings the
last launch saved at create. That is a restore, not a change: init makes them current with no
settings hook, no revision bump and no save. Every change applied later, the game's or the
menu's, hosted or not, is saved. `desc.settings_suite` NULL keeps them in the standard user
defaults, the same place the Rust runner keeps them, so a C host and the Rust demo share
the player's choice; a suite name keeps them apart (tests use a throwaway suite). The store is
`NSUserDefaults` (Foundation only) on Apple platforms; elsewhere nothing is stored. Without the
flag, nothing is read or written, and `settings_suite` must be NULL.

## What may wait in v0.1

The API never requires a call to wait. In v0.1, a few calls still do bounded work on the
caller's thread, or can wait on the system. Every row changes in a later release without an API
change.

| Call | In v0.1 | Later |
|---|---|---|
| `stickshift_context_create` | Synchronous setup: creates the Metal device and compiles the shaders (tens to a few hundred ms). `CONTEXT_READY` is queued before it returns. | Setup runs on an engine thread; `CONTEXT_READY` arrives later. |
| `stickshift_mesh_create`, `stickshift_texture_create`, `stickshift_font_create` | Upload on the caller's thread before returning (bounded by the data size; textures do not wait for mipmap generation). The resource is `READY` on return; `RESOURCE_READY` is queued (or the callback runs before the call returns). Borrowed data is released before the call returns. | Uploads move to a transfer queue; resources become ready later. |
| `stickshift_model_load_file`, `stickshift_model_load_memory` | Return at once. File read, glTF parse and image decode run on a worker thread; the GPU upload happens in the next `stickshift_poll_events` (or `stickshift_context_flush`). | Uploads use Metal fast resource loading. |
| `stickshift_frame_acquire` | Never waits. | Same. |
| `stickshift_frame_submit` | Encodes the frame on the caller's thread (bounded CPU work) and takes the next drawable from the layer, which can wait (up to about a second if the window is hidden, then `STICKSHIFT_FRAME_SKIPPED`). Never waits for the GPU. | An engine render thread does the encoding and takes the drawable; submit only queues the frame, and the newest queued frame wins. |
| `stickshift_poll_events` | Bounded housekeeping plus your callbacks. | Same. |
| `stickshift_context_flush` | **Waits** for every load and every submitted frame to finish, then delivers their events. Gives up after 60 s with `STICKSHIFT_ERROR_TIMEOUT`. Tests and tools only. | Same. |
| `stickshift_context_destroy` | **Waits** for submitted frames to finish and for a model parse in progress to end. | Same. |
| `stickshift_audio_load` | Reads and decodes the sound on the caller's thread (an engine created with `STICKSHIFT_AUDIO_SILENT` decodes nothing). A path is decoded once; loading it again is free. | Same. |
| `stickshift_model_wait` | **Waits** for one model, doing the context's model housekeeping while it waits, up to the caller's timeout. For an init hook that loads synchronously. | Same. |
| `stickshift_engine_create` | With `STICKSHIFT_AUDIO_DEVICE`, opens the default audio output (system setup, typically milliseconds). With `PERSIST_SETTINGS`, reads the user defaults. | Same. |
| `stickshift_engine_init`, `stickshift_engine_resume` | Run the game's init hook, which may load synchronously. | Same. |
| `stickshift_engine_tick` | Runs the game's hooks. Under `STICKSHIFT_FRAME_PACING_WAIT`, waits up to a second for a free frame slot; with a read-back, waits up to ten seconds for the frame. Submits as `stickshift_frame_submit` does. | Same. |
| `stickshift_engine_push_events` | A menu choice runs the settings hook. | Same. |

## Versioning and ABI

- There is **no ABI stability before 1.0**. Any release may change the API; the
  [CHANGELOG](../CHANGELOG.md) says how.
- `STICKSHIFT_API_VERSION` (a header constant) increases with every incompatible change.
  `stickshift_api_version()` returns the library's value. `StickShiftContextDesc.api_version` must be set to
  `STICKSHIFT_API_VERSION`: if it does not match the library, `stickshift_context_create` fails with
  `STICKSHIFT_ERROR_UNSUPPORTED`. That catches a header and a library from different releases.
  `StickShiftEngineDesc.api_version` is checked the same way by `stickshift_engine_create`.
- `stickshift_version_string()` returns the release, for example `"0.1.0"`.
- **`STICKSHIFT_API_MINOR`** is the additive level within `STICKSHIFT_API_VERSION`: it grows by one
  with each release that only adds. 0 is the surface before the engine object; 1 adds the engine.
  `stickshift_api_minor()` returns the library's. A host that loads the library dynamically checks
  `stickshift_api_minor() >= STICKSHIFT_API_MINOR` before it uses what its header added; a static host gets a link error instead.

**How the API grows.** Within one `STICKSHIFT_API_VERSION`, releases only add, by these rules:

1. **Sized structs.** A new struct that may grow starts with `uint32_t size` (after `api_version`
   where it has one), read and written as [Conventions](#conventions) says. New fields go at the
   end.
2. **Value types are frozen.** `StickShiftTransform`, `StickShiftStreamingConfig`,
   `StickShiftChase`, `StickShiftRenderComponent` and `StickShiftGraphicsSettings` (with its
   `reserved` slots) never change. A growable descriptor nested in another goes by pointer.
3. **Arrays of structs cross with a stride**: host events in; menu groups and items, draw records
   and quads out.
4. **Enum-like values are append-only.** An unknown value passed in is `INVALID_ARGUMENT`; a host
   treats an unknown value it reads as "other".
5. **Signatures and meanings never change.** New behaviour is a new function, a new flag bit or a
   new trailing field.
6. **Reserved ranges**: component ids 5..255 for engine components, every unnamed flag bit, and
   every `reserved` field, which must be 0.
7. **A new game hook** is a new trailing, optional field of `StickShiftGame`.
8. **Versions.** `STICKSHIFT_API_VERSION` changes only for an incompatible change, and
   `STICKSHIFT_API_MINOR` grows with each additive release.

The engine (API minor 1) was added this way: nothing a version 4 host already called changed,
except that `stickshift_context_resize` now succeeds on null contexts (it was `UNSUPPORTED`), which
only turns an error into a success. The **link line** did change, which no version check can see:
the library now carries the engine's audio, so a static host links `AudioToolbox` and `CoreAudio`
too ([Building, linking and testing](#building-linking-and-testing)).

A model is static geometry: its meshes, base-colour textures and node matrices, baked at
import. Node matrices are kept whole, so a rotated child under a non-uniformly scaled parent
draws exactly where glTF puts it. Load failures (`IO`, `PARSE`) arrive as `RESOURCE_FAILED` with a message.

`stickshift_frame_draw_model` draws every part at `world × node`.
`stickshift_frame_draw_model_ex` adds two things. A `local` matrix goes between the two, so each
part is drawn at `world × (local × node)`: a game that fits a model to its world (a scale, a turn,
a lift) passes the fit as `local` and its entity's transform as `world`. Float products are not
associative, so this grouping can differ in the last bit from passing `world × local` as one
matrix. A part filter records only the textured parts or only the untextured ones, so a game can
draw every textured surface in the frame, then other draws, then the untextured parts, in the
order it chooses.

## Example

```c
#include "stickshift.h"

StickShiftContextDesc desc = {
    .api_version = STICKSHIFT_API_VERSION,
    .backend = STICKSHIFT_BACKEND_METAL,
    .metal_layer = layer,            // a CAMetalLayer * the host owns
    .width = 1280, .height = 720, .scale = 2.0f,
};
StickShiftContext *ctx;
if (stickshift_context_create(&desc, &ctx) != STICKSHIFT_OK) {
    fprintf(stderr, "stickshift: %s\n", stickshift_last_error_message());
    return 1;
}

StickShiftModel car;
stickshift_model_load_file(ctx, "car.glb", NULL, &car);   // returns at once; PENDING

// Each display tick:
StickShiftEvent events[16];
uint32_t n;
stickshift_poll_events(ctx, events, 16, &n);
for (uint32_t i = 0; i < n; i++) {
    if (events[i].kind == STICKSHIFT_EVENT_RESOURCE_FAILED)
        fprintf(stderr, "load failed: %s\n", events[i].message);
}

StickShiftFrame *frame;
if (stickshift_frame_acquire(ctx, &frame) == STICKSHIFT_OK) {
    StickShiftMat4 view = stickshift_mat4_look_at((StickShiftVec3){0, 3, 8}, (StickShiftVec3){0, 0, 0},
                                        (StickShiftVec3){0, 1, 0});
    StickShiftMat4 proj = stickshift_mat4_perspective(0.8f, 1280.0f / 720.0f, 0.1f, 200.0f);
    StickShiftCamera camera = { stickshift_mat4_mul(proj, view), {0, 3, 8} };
    stickshift_frame_set_camera(frame, &camera);

    StickShiftMat4 world = stickshift_mat4_identity();
    stickshift_frame_draw_model(frame, car, &world, NULL);  // STICKSHIFT_NOT_READY until it loads
    stickshift_frame_submit(frame, NULL, NULL);
}

// At shutdown:
stickshift_context_destroy(ctx);
```

That host draws every frame itself. A game on the engine instead hands the loop to an engine and
draws in its render hook: [`examples/c/engine.c`](../examples/c/engine.c) is a complete one, and
[The engine](#the-engine) walks through it.

## Building, linking and testing

**Build.** `cargo build --release -p stickshift-capi` writes `target/release/libstickshift.a` and
`target/release/libstickshift.dylib`; the header is `crates/stickshift-capi/include/stickshift.h`.
The Homebrew package installs all of them (`include/stickshift/`, `lib/`) with a `stickshift.pc`.

**Link dynamically** (simplest): `-I<include dir> -L<lib dir> -lstickshift`, and make the dylib
findable through an rpath (`-Wl,-rpath,<lib dir>`, or the app bundle's `Frameworks` directory).

**Link statically:** link `libstickshift.a` plus the system frameworks and libraries the Rust code
needs. `pkg-config --static --libs stickshift` prints them for an installed package; for a checkout,
rustc reports them:

```sh
cargo rustc -p stickshift-capi --lib --crate-type staticlib -- --print native-static-libs
```

On macOS that is `-framework Metal -framework QuartzCore -framework Foundation
-framework CoreGraphics -framework CoreFoundation -framework AppKit -framework AudioToolbox
-framework CoreAudio -lobjc -liconv`. The audio frameworks are the engine's sound, and a static
host needs them even if it never creates an engine.
[`scripts/test-c-api.sh`](../scripts/test-c-api.sh) builds the C tests and the samples,
[`examples/c/offscreen.c`](../examples/c/offscreen.c) and
[`examples/c/engine.c`](../examples/c/engine.c), exactly this way.

**Testing a host without a GPU.** Create the context with `STICKSHIFT_BACKEND_NULL`: every call
behaves as on Metal (handles, states, events, frames, stats), nothing is drawn, frames complete
as they are submitted and read-backs return zeros. That keeps host-side unit tests running on
machines without Metal, including CI runners. An engine on a null context with
`STICKSHIFT_AUDIO_SILENT` and `STICKSHIFT_CLOCK_FIXED_STEP` ticks runs a game deterministically,
frame for frame as the Rust headless driver does, and `stickshift_context_get_last_frame` shows
what each frame drew.
